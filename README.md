## 10. Engenharia de Software

Engenharia de Software é a disciplina que aplica princípios, processos,
métodos e ferramentas ao desenvolvimento e à manutenção de software.

O seu objetivo não é apenas produzir código funcional. Procura criar
sistemas que satisfaçam requisitos, sejam seguros, testáveis, fiáveis,
compreensíveis e sustentáveis ao longo do tempo.

### 10.1 Requisitos funcionais

Descrevem o que o sistema deve fazer.

Exemplos deste portfólio:

- O utilizador consegue navegar até à secção de projetos.
- O utilizador consegue abrir os links dos repositórios.
- O site apresenta os contactos definidos pelo autor.

### 10.2 Requisitos não funcionais

Descrevem qualidades e restrições do sistema.

Exemplos:

- A página deve adaptar-se a ecrãs pequenos.
- Os textos devem ser legíveis e ter contraste adequado.
- Os links devem ter destinos válidos.
- O código deve ser organizado e fácil de manter.
- A navegação deve ser utilizável com teclado.

### 10.3 Ciclo de desenvolvimento

Um processo simplificado inclui:

1. Levantamento de requisitos.
2. Análise do problema.
3. Desenho da solução.
4. Implementação.
5. Testes.
6. Publicação.
7. Manutenção e melhoria.

Estas atividades podem repetir-se de forma iterativa. Não é obrigatório
executar cada uma apenas uma vez.

### 10.4 Arquitetura

A arquitetura descreve os componentes principais, as suas
responsabilidades e a forma como comunicam.

Na versão atual:

- HTML define o conteúdo.
- CSS define a apresentação.
- JavaScript controla a interatividade.
- O navegador executa o site.
- Git acompanha as alterações ao código.
- GitHub aloja o repositório.

Esta é uma arquitetura estática. Não existe backend nem base de dados
ligada ao portfólio.

### 10.5 Princípios de qualidade

- Separação de responsabilidades.
- Nomes claros e consistentes.
- Funções pequenas e com objetivos definidos.
- Evitar duplicação desnecessária.
- Validação de entradas quando aplicável.
- Tratamento de erros.
- Documentação atualizada.
- Testes proporcionais ao risco.
- Revisão de código.
- Segurança desde o desenho inicial.

### 10.6 SOLID

SOLID é um conjunto de cinco princípios usados sobretudo no desenho
de software orientado a objetos:

- **S — Single Responsibility:** uma classe deve ter uma responsabilidade
  bem definida.
- **O — Open/Closed:** o código deve permitir extensão sem exigir
  alterações constantes ao comportamento já estável.
- **L — Liskov Substitution:** implementações derivadas devem poder
  substituir os seus tipos base sem quebrar as expectativas.
- **I — Interface Segregation:** interfaces específicas são preferíveis
  a interfaces grandes que obrigam a implementar métodos desnecessários.
- **D — Dependency Inversion:** módulos de alto nível devem depender
  de abstrações, e não diretamente de detalhes concretos.

Não forces estes princípios em páginas pequenas. Aplica-os quando
ajudarem a reduzir acoplamento e facilitar a manutenção.

### 10.7 Metodologias

**Ágil:** desenvolvimento incremental, feedback frequente e adaptação.

**Scrum:** framework com papéis, eventos e artefactos definidos para
organizar trabalho complexo.

**Kanban:** visualização do fluxo de trabalho e limitação do trabalho
em progresso.

**Waterfall:** abordagem sequencial que pode ser adequada em contextos
com requisitos estáveis e fases formalizadas.

A escolha depende do contexto, do risco, da equipa e dos requisitos.

### 10.8 Testes de software

- **Unitários:** testam unidades pequenas isoladamente.
- **Integração:** verificam a comunicação entre componentes.
- **Sistema:** verificam o comportamento do sistema completo.
- **Aceitação:** verificam se os requisitos dos utilizadores foram
  satisfeitos.
- **Regressão:** verificam se alterações quebraram funcionalidades
  existentes.
- **Usabilidade e acessibilidade:** avaliam a utilização por pessoas
  com diferentes necessidades e dispositivos.

## 11. HTML5

## 12. CSS3

CSS controla cores, tipografia, disposição, espaçamento e adaptação
a diferentes tamanhos de ecrã.

Estudar:

- Cascata, herança e especificidade.
- Box model.
- Flexbox e Grid.
- Variáveis CSS.
- Pseudo-classes e estados de foco.
- Media queries.
- Transições e animações.
- Design responsivo.

Exemplo:

```css
.container {
  width: min(1100px, calc(100% - 32px));
  margin-inline: auto;
}

.cards {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1rem;
}

@media (max-width: 700px) {
  .cards {
    grid-template-columns: 1fr;
  }
}
```

Estudar:

1. Instalação e ambientes virtuais.
2. Tipos de dados e operadores.

Exemplo:

```python

    if not notas:

    return sum(notas) / len(notas)

print(calcular_media([12, 14, 16]))
```

A anotação de tipos ajuda a compreender o código, mas não substitui
a validação dos dados em tempo de execução.

## 16. Git e GitHub

Git é um sistema distribuído de controlo de versões.
GitHub é uma plataforma para alojar repositórios e colaborar.

Comandos principais:

```bash
git status
git add .
git commit -m "Atualiza o portfólio"
git log --oneline
git pull
git push
```

Fluxo recomendado:

1. Criar uma tarefa.
2. Criar uma branch quando apropriado.
3. Implementar a alteração.
4. Executar testes.
5. Rever as alterações.
6. Fazer commit com uma mensagem clara.
7. Enviar a branch.
8. Abrir um pull request se o projeto tiver revisão.
9. Integrar a alteração após validação.

Não guardes tokens, passwords ou ficheiros `.env` no repositório.

## 17. Bases de dados relacionais (SQL)

Bases relacionais organizam dados em tabelas e estabelecem relações
através de chaves.

Exemplos: SQLite, PostgreSQL e MySQL.

Conceitos essenciais:

- Tabelas, linhas e colunas.
- Chave primária.
- Chave estrangeira.
- Relações entre entidades.
- SELECT, INSERT, UPDATE e DELETE.
- JOIN, índices e restrições.
- Transações.
- Normalização.
- Cópias de segurança.

Exemplo:

```sql
CREATE TABLE alunos (
    id INTEGER PRIMARY KEY,
    nome VARCHAR(120) NOT NULL,
    email VARCHAR(180) UNIQUE
);

INSERT INTO alunos (id, nome, email)
VALUES (1, 'Ana Manuel', 'ana@example.com');

SELECT id, nome
FROM alunos
ORDER BY nome;
```

A sintaxe concreta varia consoante o motor de base de dados.

## 18. Bases de dados documentais (NoSQL)

Bases documentais guardam registos em documentos, frequentemente
representados com estruturas semelhantes a JSON.

MongoDB é um exemplo.

Conceitos essenciais:

- Bases de dados e coleções.
- Documentos e campos.
- Arrays e objetos aninhados.
- Consultas e filtros.
- Atualizações.
- Índices.
- Validação de documentos.
- Modelação por incorporação ou referência.
- Segurança, permissões e backups.

Exemplo de documento:

```json
{
  "nome": "Ana Manuel",
  "curso": "Informática",
  "ativo": true,
  "competencias": ["HTML", "CSS", "JavaScript"]
}
```

Exemplo de consulta MongoDB:

```javascript
db.alunos.find({ ativo: true });
```

### SQL ou NoSQL?

SQL é uma boa escolha quando relações, integridade referencial e
transações são centrais. Bases documentais podem ser adequadas quando
o modelo documental e os padrões de consulta favorecem essa estrutura.

Não é obrigatório usar as duas no mesmo projeto. Escolhe com base nos
requisitos, nas consultas, na consistência e na capacidade de manutenção.

## 19. APIs e arquitetura cliente-servidor

Uma API permite que sistemas comuniquem através de operações definidas.

Numa arquitetura comum:

- Frontend: interface utilizada pelo utilizador.
- Backend: regras de negócio e validações.
- API: contrato de comunicação.
- Base de dados: persistência.
- Autenticação: identificação do utilizador.
- Autorização: definição do que pode fazer.

HTTP inclui métodos como GET, POST, PUT, PATCH e DELETE.
Uma API deve validar entradas, controlar permissões e devolver erros
coerentes. Nunca confies apenas na validação feita no frontend.

## 20. Segurança

Princípios básicos:

- Validar entradas no servidor.
- Aplicar autorização em cada operação protegida.
- Usar consultas parametrizadas ou mecanismos seguros do ORM.
- Guardar passwords com algoritmos apropriados de hash.
- Proteger sessões e tokens.
- Guardar segredos em variáveis de ambiente ou gestores de segredos.
- Limitar permissões de contas e serviços.
- Manter dependências atualizadas.
- Fazer backups e testar a recuperação.
- Registar eventos importantes sem expor dados sensíveis.

A segurança depende também da configuração, da infraestrutura e
dos processos de desenvolvimento.
